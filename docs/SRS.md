# 소프트웨어 요구사항 명세서 (Software Requirements Specification)

**프로젝트명**: Berry_WHAT 스마트 온실 제어 시스템
**문서 버전**: 1.0
**작성자**: HAgent (System Architect)

---

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)
본 문서는 정밀 농업을 위한 오픈소스 스마트 온실 제어 솔루션인 **Berry_WHAT** 프로젝트의 기능적 및 비기능적 요구사항을 명시합니다. 이 문서는 시스템 설계, 개발, 검증 및 유지보수의 기준 자료로 활용됩니다.

### 1.2 범위 (Scope)
Berry_WHAT 시스템은 온실 내부의 기후 환경(온도, 습도, 일사량 등)을 모니터링하고 데드밴드(Deadband) 기반의 공조 제어를 수행합니다. 또한, 호겐도른(Hoogendoorn) 방식의 정밀 관수 및 양액 혼합 제어(EC, pH, 수온 제어) 기능을 포함하여 최적의 작물 생육 환경을 자동화합니다. 관리자는 로컬 웹 대시보드를 통해 실시간 상태를 확인하고 제어 임계값을 수정할 수 있습니다.

### 1.3 용어 정의 (Definitions)
* **VPD (Vapor Pressure Deficit)**: 포차. 식물의 증산작용을 나타내는 지표로 온도와 습도를 기반으로 계산됨.
* **Deadband**: 설정된 목표값 주변에 위치하여 제어 동작이 발생하지 않는 오차 허용 구간. (예: 목표온도 ± 데드밴드)
* **PID 제어**: 비례(P), 적분(I), 미분(D) 연산을 통해 목표값에 도달하기 위한 정밀 밸브/모터 제어 방식. (본 시스템에서는 P-Band를 적용한 비례 제어 위주 적용)
* **EC (Electrical Conductivity)**: 전기전도도. 양액에 녹아있는 비료의 농도를 의미함.
* **Solar Summation (일사 적산)**: 누적된 광 에너지를 계산하여 관수 시점을 결정하는 방식.

## 2. 전체 설명 (Overall Description)

### 2.1 시스템 환경 (System Perspective)
시스템은 크게 세 가지 계층으로 구성됩니다.
1. **데이터 수집부 (Data Collector)**: Modbus RTU 또는 시뮬레이션 기반의 센서 데이터 취득 (온도, 습도, 일사량, 수분, EC, pH, 유량, 수위 등).
2. **코어 로직 (Core Engine)**: Python 기반의 제어 상태 머신 및 알고리즘 모듈. (기후 제어 및 양액/관수 제어).
3. **사용자 인터페이스 (Web UX)**: Flask 및 Chart.js 기반의 실시간 모니터링 및 제어 파라미터 입력 대시보드.

### 2.2 주요 기능 요약 (Product Functions)
* 환경 센서 실시간 수집 및 파생 지표(VPD, 일사적산) 자동 계산
* 목표 온도 및 데드밴드 기반의 기후 기기(환기창, 팬, 히터) 자동 제어
* 일사 적산량 및 토양 수분 임계값 기반의 자동 관수 스케줄링
* EC/pH 비례대(P-Band) 및 목표 수온을 반영한 정밀 양액 혼합 제어
* 믹싱 탱크 수위 및 EC 수온의 극한값 감지 시 펌프 강제 차단(Alarm) 보호 기능
* SQLite DB 기반의 주기적 데이터 저장 및 이력 그래프 시각화 팝업 제공

### 2.3 제약 사항 (Constraints)
* 본 시스템은 Python 3.10 이상의 환경에서 구동되어야 함.
* 센서 제어 주기는 시스템 부하를 고려해 기본 2초 간격으로 스케줄링됨.
* 로컬 네트워크 기반 동작을 원칙으로 하며, 외부 클라우드 의존성 없이 로컬 SQLite DB만 사용함.

## 3. 구체적인 요구사항 (Specific Requirements)

### 3.1 기능적 요구사항 (Functional Requirements)

#### 3.1.1 환경 데이터 모니터링
* **FR-01**: 시스템은 대기 센서(온도, 습도, 일사량) 및 토양 센서(수분, EC, pH, 토양온도) 데이터를 수집해야 한다.
* **FR-02**: 양액 제어를 위해 유량(Flow Rate), 관수 수온(Water Temp), 믹싱 탱크 수위(Tank Level), EC 수온(EC Temp) 데이터를 추가 수집해야 한다.
* **FR-03**: 수집된 온습도 데이터를 바탕으로 VPD(포차)를 실시간으로 계산해야 한다.
* **FR-04**: 실시간 일사량 데이터를 적분하여 일사적산(Solar Accumulation) 값을 갱신해야 한다.

#### 3.1.2 기후 공조 제어 (Climate Control)
* **FR-05**: 사용자는 웹 대시보드에서 '목표 온도'와 '데드밴드'를 설정할 수 있어야 한다.
* **FR-06**: `(현재 온도) > (목표 온도 + 데드밴드)` 일 경우 환기창 개방(OPEN_VENTS) 동작을 수행해야 한다.
* **FR-07**: `(현재 온도) < (목표 온도 - 데드밴드)` 일 경우 환기창 폐쇄 및 히터 가동을 수행해야 한다.

#### 3.1.3 정밀 양액 및 관수 제어 (Precise Fertigation & Irrigation)
* **FR-08**: 사용자는 각 관수 구역별로 목표 EC, 일사 임계값, 시작/종료 시간, 관수 간격을 설정할 수 있어야 한다.
* **FR-09**: 일사적산값이 임계값을 초과하거나, 토양 수분이 하한치 이하로 떨어지면 관수 프로세스를 시작해야 한다. (상태: STANDBY -> PRE_RINSE -> MIXING -> STABILIZATION -> IRRIGATION -> POST_RINSE).
* **FR-10**: 양액 혼합(MIXING) 시, 사용자가 설정한 `ec_p_band`, `ph_p_band`, `flow_pre_control`, `target_water_temp`에 기반하여 비료 밸브(A액, B액, 산성) 개방률과 온수 믹싱 밸브를 제어해야 한다.
* **FR-11 (알람 제어)**: 시스템 동작 중 '믹싱 탱크 수위'가 10% 이하로 떨어지거나, 'EC 수온'이 5°C 미만 또는 35°C를 초과할 경우 시스템을 즉시 ALARM 상태로 전환하고 모든 급수 펌프를 차단(Off)해야 한다.

#### 3.1.4 웹 대시보드 및 데이터 이력
* **FR-12**: 웹 화면에는 최소 10개의 핵심 모니터링 지표가 갱신 주기마다 깜빡임 없이 비동기로 표출되어야 한다.
* **FR-13**: 사용자가 특정 모니터링 박스(예: 온도, 유량)를 클릭하면 화면 중앙에 모달(Modal) 팝업이 열려야 한다.
* **FR-14**: 팝업에는 Chart.js를 이용해 최근 저장된 60건의 해당 데이터 이력이 꺾은선 그래프로 시각화되어야 한다.
* **FR-15**: 데이터베이스(`sensor_data` 테이블)는 5번의 갱신 루프(약 10초)마다 한 번씩 모든 센서 데이터를 영구 저장해야 한다.

### 3.2 비기능적 요구사항 (Non-Functional Requirements)

* **NFR-01 (반응성)**: 웹 인터페이스에서 제어값을 적용(API POST)했을 때 시스템 내부 로직에 반영되는 지연 시간은 1초 미만이어야 한다.
* **NFR-02 (확장성)**: 새로운 센서나 구동부(Actuator)가 추가되더라도 기존 코어를 수정하지 않고 모듈(Class) 형태로 확장 가능한 아키텍처를 유지해야 한다.
* **NFR-03 (무결성)**: 센서 통신 오류 발생 시, 펌프 및 환기창 등 주요 물리적 구동 장치는 1분 이내에 기본 안전 상태(대기 및 폐쇄)로 복귀해야 한다.
